The terminal is a text window where you type commands and the computer answers in text. It is the same idea as a file manager, except you name the folder instead of clicking it. This session’s goal is to get comfortable there, then use that comfort for two things almost every project needs: a shell script and a Git commit.

You do not need to finish both tracks. Beginners should complete the beginner steps. If those already feel familiar, skip ahead to the advanced track and push one skill further.

The command lists below build on the first-commands writeup from the Git tutorial and the “do one repetitive job” idea from Automate Your Life. Work only inside a folder you create for practice.

Open a terminal

  • macOS — Open Terminal (Applications → Utilities), or the terminal built into VS Code or Cursor.
  • Windows — Install Git for Windows and open Git Bash. The steps below assume Git Bash so they match macOS and Linux. PowerShell can navigate too, but bash scripts need Git Bash or WSL.
  • Linux — Open the app named Terminal, Konsole, or GNOME Terminal. Ctrl+Alt+T works on many desktops.

The line waiting for you is the prompt. It usually ends in $ or %. You type after that and press Enter. A blinking cursor with no new prompt means a command is still running; Ctrl+C stops it.

How a command is shaped

Almost every line you type has the same parts:

command  argument  argument
ls       -la       Documents
  • Command — The program to run (ls, cd, git).
  • Arguments — Extra words that change what it does. Flags start with - or -- (-la, --oneline).
  • Working directory — The folder you are “in.” Commands act there unless you give them a path.

Paths use / even on Windows Git Bash. . means “here,” .. means “the parent folder,” and ~ means your home folder. Put quotes around names that contain spaces: cd "My Documents".

Beginner track

Leave with three things: you can move around the disk, you ran a five-line script, and you made one Git commit. Do the steps in order. If a command prints an error, read the first line of the error before you retype anything.

1. See where you are

pwd
ls
ls -la
  • pwd prints the current folder (print working directory).
  • ls lists names in that folder.
  • ls -la includes hidden files (names starting with .) and details such as size.

2. Make a practice folder and go inside it

cd ~
mkdir apl-terminal-practice
cd apl-terminal-practice
pwd

cd changes directory. After this, pwd should end in apl-terminal-practice. Stay in this folder for the rest of the beginner track. cd .. steps up one folder; cd ~ jumps home.

3. Create, read, copy, and remove a file

echo "Hello from the terminal" > notes.txt
cat notes.txt
cp notes.txt notes-copy.txt
mv notes-copy.txt greeting.txt
ls
rm greeting.txt
ls
  • > sends output into a file and replaces whatever was there. >> adds to the end instead.
  • cat prints a file.
  • cp copies. mv renames or moves.
  • rm deletes immediately. It does not go to the trash. Only remove files you created in this practice folder.

4. Ask the computer what a command does

ls --help
man ls

man opens the manual. Press q to leave it. The up arrow recalls the previous command. Tab completes a folder or file name after you type the first few letters. clear wipes the screen without deleting files.

5. Write a tiny shell script

A shell script is a text file of commands the shell runs top to bottom. Create hello.sh in your practice folder (use any editor, or the cat trick below). The first line, the shebang, says “run this with bash.”

cat > hello.sh <<'EOF'
#!/usr/bin/env bash
name="${1:-friend}"
echo "Hello, $name."
echo "You are in $(pwd)."
EOF
chmod +x hello.sh
./hello.sh
./hello.sh Ada
  • chmod +x marks the file as runnable.
  • ./hello.sh runs it. The ./ means “in this folder,” which is required for scripts you just wrote.
  • $1 is the first word you typed after the script name. If you omit it, the script uses friend.

6. Save that work with Git

These are the same first commands from the Git tutorial. Install Git first if git --version fails (git-scm.com/downloads).

git --version
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git init
git status
git add hello.sh notes.txt
git status
git commit -m "Add a hello script and notes"
git log --oneline
git status
  • git status is the map. Run it whenever you are unsure.
  • git add chooses what goes into the next snapshot. git commit saves that snapshot with a message about why.
  • git log --oneline shows the history. You should see one commit.

Pushing to GitHub is optional today. When you are ready, the Git for Beginners workshop covers a pull request on the Hello-World repo.

Beginner finish line

  • You can explain what pwd, ls, and cd do.
  • ./hello.sh prints a greeting from your practice folder.
  • git log --oneline shows your commit.

Advanced track

You already know how to move around. This track is about combining commands, writing a script that makes a decision, and reading Git history on purpose. Still work inside ~/apl-terminal-practice (create it with the beginner step 2 if you skipped here).

1. Connect commands with pipes

A pipe (|) sends one command’s output into the next command’s input.

printf 'apple\npear\napricot\nplum\n' > fruit.txt
cat fruit.txt
grep '^ap' fruit.txt
wc -l fruit.txt
sort fruit.txt | uniq
cat fruit.txt | grep ap | wc -l
  • grep prints lines that match a pattern. ^ap means “starts with ap.”
  • wc -l counts lines.
  • sort orders lines. uniq collapses neighbors that are identical, so sort first.

Try the same idea on a real folder, without changing it:

ls -la ~ | head
ls ~ | wc -l

2. Find out which program you are running

echo "$SHELL"
which bash
which git
type ls
echo "$PATH"

PATH is the list of folders the shell searches when you type a command. which shows the file it found. If a tool is “not found,” it is usually missing from PATH or not installed — not a typo in the rest of your script.

3. Write a script with a check and a loop

This script lists regular files in the current folder and their extensions. It prints only. It does not rename or delete anything. That dry-run habit is the same safety rule as in Automate Your Life.

cat > list-files.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

target="${1:-.}"
if [[ ! -d "$target" ]]; then
  echo "Not a folder: $target" >&2
  exit 1
fi

shopt -s nullglob
count=0
for file in "$target"/*; do
  if [[ -f "$file" ]]; then
    base="${file##*/}"
    ext="${base##*.}"
    if [[ "$base" == "$ext" ]]; then
      ext="(none)"
    fi
    echo "$ext	$base"
    count=$((count + 1))
  fi
done
echo "---"
echo "$count file(s) in $target"
EOF
chmod +x list-files.sh
./list-files.sh
./list-files.sh ~
./list-files.sh /this/does/not/exist
  • set -euo pipefail stops the script on errors, unset variables, and failed pipes. Turn it on in scripts you keep.
  • [[ ! -d ]] checks “this is not a folder.” The message goes to stderr (>&2) and the script exits with status 1, which means failure.
  • The for loop visits each match of "$target"/*. Quotes matter when names contain spaces.

Stretch: change the script so a second argument is an extension filter (./list-files.sh . txt prints only .txt files). Keep the dry-run. Do not add rm or mv until the printed plan looks right.

4. Read Git like a logbook

From the practice repo (run git init and make the beginner commit first if you do not have one):

echo "A second line" >> notes.txt
git diff
git add notes.txt
git commit -m "Note what a pipe does"
git log --oneline
git show HEAD
git checkout -b practice/pipes
echo "branch note" >> notes.txt
git add notes.txt
git commit -m "Experiment on a branch"
git log --oneline --graph --all
git switch -
  • git diff shows unstaged edits. Read it before you commit.
  • A branch is a movable name for a commit. practice/pipes keeps the experiment off your first line of history.
  • git switch - returns to the previous branch. git switch is the current spelling of git checkout for changing branches.

Do not rewrite history that you have already pushed, and do not force-push to main. Merging and conflicts are covered in Git for Beginners and Learn Git Branching.

5. Check the script before you trust it

Paste list-files.sh into ShellCheck, or install the shellcheck command and run shellcheck list-files.sh. Fix the warnings it prints. Then run the script on a folder of sample files and confirm the count matches ls.

Advanced finish line

  • You can explain a pipe in one sentence and demonstrate grep plus wc.
  • list-files.sh handles a missing folder without deleting anything.
  • git log --oneline --graph --all shows at least two commits, and you can point at which branch each one is on.

Commands worth memorizing

CommandWhat it does
pwdPrint the folder you are in.
lsList names here. ls -la shows details and hidden files.
cdMove to another folder. cd .. goes up. cd ~ goes home.
mkdirCreate a folder.
catPrint a file. head and tail print the start or end.
cp / mv / rmCopy, move or rename, delete. rm skips the trash.
echoPrint text. > writes a file; >> appends.
grepPrint lines that match a pattern.
|Send one command’s output into the next command.
chmod +xAllow a script to be executed.
man / --helpRead the manual for a command.

Git, once the files exist

git status
git add .
git commit -m "Short message about why"
git log --oneline
git push
git pull

Always run git status when unsure. What it prints is the map of where you are. git add . stages everything in this folder, including files you may not have meant to save — git status before git commit catches that.

Habits that prevent bad afternoons

  • Practice in a folder you created, not in your home directory and not in a system folder.
  • Read a command before you press Enter, especially if it contains rm, sudo, or a pasted curl.
  • Prefer a script that prints the plan, then a second run that changes files.
  • Commit small. A message like “Add hello script” is useful; “update” is not.
  • Ctrl+C cancels a running command. Closing the window does not undo rm.
